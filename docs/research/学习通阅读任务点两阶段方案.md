# 学习通阅读任务点两阶段方案

> 研究日期：2026-09-26
>
> 状态：方案已落盘，尚未开发、尚未提交
>
> 范围：针对学习通课程章节中的“阅读”任务点，例如截图中的《幸福之路》阅读任务。本文不把普通作业中的“阅读理解题”与阅读任务点混为一谈。

## 1. 任务定义

本任务要解决的是学习通的独立阅读任务点：页面要求学生点击“去阅读”，阅读指定内容并累计阅读时长，随后由平台确认任务完成。

它与以下功能不同：

- **普通阅读理解题**：出现在作业、测验或考试中，可以走现有题目查询和答案填充流程。
- **阅读任务点**：出现在章节内容页，包含书籍或专题、阅读时长和“去阅读”入口，不以 `.TiMu` 题目列表为主要结构。

本方案只处理第二种场景。

## 2. 当前场景快照

### 2.1 页面来源

- 浏览器：Codex 内置浏览器
- 页面类型：学习通学生学习页面
- 课程章节：章节标题显示为“阅读”
- 书籍：`幸福之路`，作者显示为`（英）罗素`
- 页面提示：阅读课程拓展专题计入成绩；点击“去阅读”可完成阅读任务点
- 当前可见时长：`0.0` 分钟
- URL 记录策略：只记录域名、路径和参数名，不保存完整课程 URL、`enc`、`cpi`、`clazzid` 等会话参数

### 2.2 已观察到的嵌套结构

```text
studentstudy
└─ #iframe
   └─ mooc-ans/knowledge/cards
      └─ ananas/modules/read/indexV2.html
         └─ mooc-ans/coursedata/readjobv2/show
```

已确认的路径特征：

- 外层学生页：`/mycourse/studentstudy`
- 章节卡片页：`/mooc-ans/knowledge/cards`
- 阅读模块外壳：`/ananas/modules/read/indexV2.html`
- 阅读任务展示页：`/mooc-ans/coursedata/readjobv2/show`

### 2.3 本轮浏览器观测结果

1. 学生学习页可以直接看到阅读模块和书籍条目。
2. 阅读模块显示当天阅读总时长，并提供“去阅读”入口。
3. 入口点击后可访问性结构发生变化，但在本轮中没有拿到可靠的新阅读器 URL、网络请求或完成响应。
4. 随后浏览器连接出现认证传输错误，不能把这次点击当作“阅读已打开”或“任务已完成”的证据。

因此，当前证据只足以确认入口和嵌套结构，不能证明计时、心跳、翻页和完成接口的实现细节。

## 3. 当前代码缺口

用户脚本的章节任务分发位于 [`scripts/userscript/学习通脚本.js`](../../scripts/userscript/学习通脚本.js)：

- `video/index.html` 进入视频流程；
- `work/index.html` 进入作业流程；
- `audio/index.html` 进入音频流程；
- `pdf/index.html` 进入文档流程；
- 其他模块进入“未知任务跳过”。

当前没有 `read/indexV2.html` 或 `readjobv2/show` 的分支，所以脚本不会自动：

- 点击“去阅读”；
- 识别阅读器是否打开；
- 记录或维持阅读状态；
- 读取服务端确认的阅读进度；
- 在完成前阻止章节自动切换。

现有题库接口、AI 答题和 `fillAnswer` 只服务于题目查询，不是阅读任务点的处理入口。

## 4. 两阶段总览

| 阶段 | 目标 | 允许的动作 | 产出 | 结束门槛 |
| --- | --- | --- | --- | --- |
| 阶段一：机制确认 | 确认阅读器入口、计时、心跳和完成判定 | 只读观察、正常点击、记录 DOM/网络/状态变化 | 脱敏观测记录、状态模型、接口证据 | 至少一次完整的开始到完成链路，或明确记录无法完成的阻断点 |
| 阶段二：工程实现 | 将已确认机制接入用户脚本并可回归测试 | 修改脚本、增加配置、增加测试、现场验证 | 阅读任务处理器、回退策略、测试和文档 | 完成状态由平台权威信号确认，异常时不误跳过 |

两阶段之间有硬性决策门：**没有阶段一的真实完成信号证据，不进入阶段二的接口实现。**

## 5. 阶段一：机制确认详细方案

### 5.1 目标

回答以下问题：

1. 点击“去阅读”后，是同页跳转、弹窗、内嵌 iframe，还是新标签页。
2. 阅读器的真实 URL 和 DOM 容器是什么。
3. 阅读时长由前端计时、定时心跳，还是滚动/翻页事件驱动。
4. 哪些请求负责上报进度，响应如何表示成功或失败。
5. 平台如何把阅读过程变为章节完成状态。
6. 阅读器在后台标签页、切回、刷新和短暂停留时的行为。

### 5.2 观测前准备

- 使用当前已经登录的同一课程和同一章节。
- 保留 Network 日志，开启 Preserve log；不修改请求、不重放请求。
- 记录开始前页面的阅读时长、任务勾选状态和 iframe 层级。
- 所有日志只保留路径、方法、状态码、脱敏后的参数名和关键业务字段。
- 禁止把 Cookie、Authorization、完整 `enc`、完整课程 URL 或个人账号信息写入仓库。

### 5.3 入口与阅读器观测

按以下顺序操作并记录每一步：

1. 记录父页面 URL 路径、阅读模块 iframe 的 `src` 路径。
2. 点击“去阅读”。
3. 检查以下变化：
   - 是否出现新标签页或弹窗；
   - 当前 URL 是否变化；
   - iframe 数量、`src` 和标题是否变化；
   - 页面是否出现关闭、返回、下一页、目录或进度控件。
4. 记录阅读器的最小 DOM 信息：根容器、正文容器、页码/章节标识、可滚动元素、完成或返回按钮。
5. 不直接猜测接口名称；接口以浏览器实际发出的请求为准。

### 5.4 计时与进度观测

至少做四个短实验，每个实验只观察，不批量操作：

| 实验 | 操作 | 记录重点 |
| --- | --- | --- |
| A | 打开阅读器后停留 60-120 秒 | 时长是否增加、请求间隔、页面状态 |
| B | 停留期间滚动或翻到下一页 | 是否触发额外请求、进度是否跳变 |
| C | 切换到后台 30-60 秒再返回 | 心跳是否继续、是否暂停累计、是否出现风控提示 |
| D | 刷新阅读器或返回父页面后重新进入 | 服务端进度是否保留、任务状态是否变化 |

每次实验记录：

- 墙钟时间；
- 页面显示阅读时长；
- 当前页码或内容标识；
- 可见的完成/未完成状态；
- 请求路径、方法、状态码和响应中的脱敏业务字段；
- 请求前后页面状态变化。

### 5.5 网络请求确认

只筛选阅读器域名的 `fetch`/`XHR`/文档请求，重点查找包含下列语义的请求：

- 任务标识：`jobid`、`djobid`、`knowledgeid`；
- 课程上下文：`courseid`、`clazzid`、`cpi`；
- 阅读进度：`readTime`、`watchTime`、`duration`、`progress`、`page`、`chapter`；
- 状态动作：`start`、`heartbeat`、`finish`、`complete`、`update`。

对候选请求逐条记录：

1. 发生时间和相邻请求间隔；
2. HTTP 方法和脱敏路径；
3. 状态码；
4. 请求体/查询参数中字段名及字段类型，不记录敏感值；
5. 响应中的成功标志、进度字段和错误码；
6. 请求失败后页面是否重试、停止计时或显示提示。

### 5.6 阶段一验收标准

满足以下条件才算完成机制确认：

- 能明确描述“去阅读”后的真实阅读器承载方式；
- 至少观察到一次开始阅读后的计时或进度变化；
- 至少识别出一个与阅读进度或状态相关的真实请求，或明确证明进度由父页面事件完成；
- 能区分“阅读器打开”“正在阅读”“达到完成条件”“父页面显示完成”四个状态；
- 至少一次验证返回父页面后，完成状态是否发生变化；
- 形成一份脱敏观测记录，足以让开发者复现实验；
- 若无法完成上述条件，必须把阻断点记录为结果，不能用猜测替代。

### 5.7 阶段一产出物

建议产出以下文件或记录：

- `docs/research/学习通阅读任务点机制观测.md`：实际 DOM、URL 路径、请求和状态变化；
- 脱敏后的本地 Network 摘要；如保存 HAR，只放在仓库外；
- 阅读任务状态转换图；
- “可实现字段”和“禁止猜测字段”清单；
- 阶段二的接口和验收约束。

## 6. 阶段二：工程实现详细方案

### 6.1 设计原则

1. 阅读任务点使用独立处理器，不复用题目 `getQuestion`/`fillAnswer` 流程。
2. 优先触发页面已有的“去阅读”事件；只有阶段一确认后才封装具体请求。
3. 不伪造阅读时长、不强行写入完成标志、不跳过服务端校验。
4. 没有收到权威完成信号时，默认保持当前章节，不自动跳过。
5. 所有日志脱敏，不能输出完整课程 URL、Cookie、令牌或个人标识。

### 6.2 建议状态机

```text
DISCOVERED
  -> OPENING
  -> READING
  -> REPORTING
  -> COMPLETING
  -> VERIFIED

任意阶段 -> BLOCKED / TIMEOUT / ERROR
```

状态含义：

| 状态 | 进入条件 | 允许动作 | 离开条件 |
| --- | --- | --- | --- |
| `DISCOVERED` | 发现阅读模块路径 | 读取 DOM 和入口 | 找到可点击入口 |
| `OPENING` | 已触发“去阅读” | 等待阅读器、弹窗或新标签页 | 发现阅读器，或超时 |
| `READING` | 阅读器可用 | 记录页面状态，按页面机制维持会话 | 收到进度变化或阅读器结束 |
| `REPORTING` | 需要定时上报 | 仅执行阶段一确认过的正常动作 | 请求成功、重试或失败 |
| `COMPLETING` | 达到平台要求或收到完成响应 | 回到父页面并重新查询状态 | 父页面确认完成，或确认失败 |
| `VERIFIED` | 父页面显示完成或权威接口返回完成 | 允许自动切换 | 任务结束 |
| `BLOCKED` | 登录、风控、弹窗、跨域等阻断 | 停止自动化并提示用户 | 用户处理后重新进入 |
| `TIMEOUT` | 等待超过上限 | 保留现场诊断信息，不跳过 | 用户重试或手动继续 |

### 6.3 用户脚本接入点

在章节任务分发处增加阅读模块检测，检测特征至少包括：

- iframe 路径匹配 `/ananas/modules/read/`；
- 内部页面路径匹配 `/mooc-ans/coursedata/readjobv2/show`；
- 任务上下文包含阅读标题或阅读入口。

处理器建议提供以下最小接口：

```text
detectReadingTask(context) -> ReadingTask | null
openReading(task) -> ReaderHandle
observeReading(handle) -> ReadingSnapshot
waitForCompletion(task, handle) -> CompletionResult
cleanupReading(handle) -> void
```

接口只表达任务语义，具体 URL、请求字段和页面选择器由阶段一观测结果注入，避免把猜测固化到主流程。

### 6.4 与自动切换的关系

当前脚本在任务循环末尾会根据配置点击“下一章节”。阅读处理器接入后必须改变这个顺序：

1. 发现阅读任务；
2. 执行阅读状态机；
3. 得到 `VERIFIED` 后才允许自动切换；
4. 得到 `BLOCKED`、`TIMEOUT` 或 `ERROR` 时停止自动切换，并在运行日志中说明原因。

这是本功能的核心保护，避免“阅读任务被当作未知任务跳过”。

### 6.5 配置建议

配置名称以阶段一结果为准，建议先设计而不立即暴露全部选项：

- `autoReading`：是否自动处理阅读任务，初始默认关闭，稳定后再评估默认值；
- `readingMaxWaitSeconds`：阅读器打开和完成确认的最长等待时间；
- `readingDiagnosticsEnabled`：是否记录脱敏的阅读状态摘要；
- `readingAutoAdvance`：完成确认后是否允许进入下一章节。

如果平台要求真实停留时长，不能提供“任意缩短阅读时间”的配置；配置只能控制等待上限、诊断和章节切换策略。

### 6.6 测试方案

#### 离线测试

- URL 识别：能识别阅读模块外壳和 `readjobv2/show`，不会误识别视频、音频、作业、PDF。
- 状态转换：正常、超时、阻断、接口错误都进入预期状态。
- 完成保护：未收到 `VERIFIED` 时不会调用下一章节点击。
- 日志脱敏：输入带有 `enc`、`cpi`、`clazzid` 的 URL，输出不含敏感值。
- 清理逻辑：阅读器关闭或章节切换后，轮询器和观察器被释放。

#### 浏览器验收

- 在真实课程中打开阅读任务；
- 能从父页面进入阅读器；
- 阅读器停留/翻页行为与阶段一记录一致；
- 返回后父页面显示的时长或完成状态与平台一致；
- 未完成或异常时不会自动跳过该章节；
- 完成后才会执行一次自动切换，且不会重复启动多个阅读处理器。

### 6.7 阶段二完成门槛

只有同时满足以下条件，才可以认为功能完成：

- 有真实平台完成信号，而非仅凭本地计时；
- 有针对阅读模块的回归测试；
- 有至少一次真实课程浏览器验收；
- 失败时不误报完成、不误跳章节；
- 日志和导出内容不泄露会话参数；
- 用户确认现场行为无问题后，才进行 Git 提交。

## 7. 风险与回退

| 风险 | 影响 | 处理方式 |
| --- | --- | --- |
| 阅读器由新窗口承载 | 脚本上下文无法自动获取 | 先记录新窗口 URL 和可访问性；无法绑定时进入 `BLOCKED` |
| 跨域 iframe 限制 | 不能直接读取内部 DOM | 依赖父页面可见状态或浏览器扩展允许的同源边界；不绕过浏览器安全策略 |
| 阅读时长由服务端计算 | 本地计时不等于有效时长 | 以服务端响应和父页面状态为准 |
| 页面结构经常变化 | 选择器失效 | 选择器集中管理，增加路径和文本兜底，并保留诊断信息 |
| 网络请求失败或风控 | 任务无法确认完成 | 停止自动切换，提示用户，不重放或伪造请求 |
| 浏览器连接不可用 | 无法完成机制验证 | 保留当前已确认结构，标记阶段一未完成，等待下一次现场观测 |
